# Apply Suggestion

Review and apply pending structural suggestions generated by Auto Context.

## Arguments

- No argument: list all pending suggestions, ask user to select
- `{id}`: apply specific suggestion by ID (e.g., `/cac-apply 001`)
- `all`: apply all pending suggestions sequentially

## Procedure

### Step 1: Scan pending suggestions

1. Read all `.md` files in `.claude-auto-context/suggestions/`
2. Filter: skip files containing the line `applied`, `rejected`, or `failed`
3. Remaining files are pending suggestions

### Step 2: No argument — interactive selection

1. Display numbered list of pending suggestions (ID + title)
2. If 0 pending: output "대기 중인 suggestion이 없습니다." and stop
3. Use AskUserQuestion to let user select which suggestion(s) to apply

### Step 3: Apply selected suggestion

For each selected suggestion:

1. Read the full suggestion file
2. Identify the proposal section (`## Proposal` or `## Proposed Remediations` or any section describing what to change)
3. Execute the proposed changes:
   - Read target files mentioned in proposal
   - Apply the suggested modifications (Write/Edit)
   - If proposal involves file splits: create new files, update imports
4. Verify: run existing tests if available (`bun test`, `npm test`, etc.)
5. Update the suggestion file: append status block at the end
6. Output summary of changes made

### Step 4: `all` argument

Repeat Step 3 for every pending suggestion, sequentially.
Stop on first failure and report which suggestion failed.

## Status Update Format

After applying, append to the end of the suggestion file:

```markdown

## Status
applied

## Applied At
{ISO 8601 timestamp}

## Changes Made
- {file}: {description}
- {file}: {description}
```

## Error Handling

- If suggestion references files that don't exist: skip with warning
- If tests fail after applying: revert changes, mark suggestion status as `failed` instead of `applied`, report to user
- If suggestion is ambiguous: ask user for clarification before proceeding

## Anti-Patterns

- Do NOT apply without reading the full suggestion first
- Do NOT skip test verification if tests exist
- Do NOT modify the suggestion's Problem/Evidence sections
- Do NOT apply a suggestion that is already `applied`, `rejected`, or `failed`
