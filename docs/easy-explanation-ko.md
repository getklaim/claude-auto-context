# Auto Context 플러그인 — 쉬운 설명

## 이게 뭐야?

Claude Code라는 AI가 코딩을 도와주는 프로그램이 있어. 근데 이 AI는 매번 새로 대화를 시작하면 이전에 뭘 했는지 다 까먹어. 마치 금붕어처럼.

Auto Context는 이 금붕어한테 일기장을 만들어주는 플러그인이야.

---

## 크게 두 가지로 나뉘어

```
📥 Input (알려주기)              📤 Output (관찰하고 배우기)
"이 프로젝트는 이렇게 해"        "아, 이 사람은 이렇게 코딩하는구나"
```

---

## 📥 Input — Rules 파일로 알려주기

프로젝트 폴더에 규칙 파일을 넣어두면, Claude가 그 파일을 건드릴 때 자동으로 규칙을 읽어.

```
.claude/rules/
  auth.md     → "인증 코드는 이렇게 써"
  api.md      → "API는 이렇게 만들어"
  database.md → "DB는 이렇게 다뤄"
```

마치 교실 벽에 붙어있는 수칙 같은 거야. "복도에서 뛰지 마세요"처럼, Claude가 auth 폴더에서 작업하면 auth.md 수칙이 자동으로 보이는 거지.

### 왜 이렇게 해?

다른 방법은 매번 대화 시작할 때 모든 규칙을 한꺼번에 쏟아붓는 건데, 그건 마치 아침 조회 때 교칙 100개를 다 읽어주는 거랑 같아. 필요한 것만, 필요할 때 보여주는 게 훨씬 나아.

### "암묵지"란?

코드를 아무리 읽어봐도 알 수 없는 것이 있어. 예를 들어:

| 종류 | 예시 |
|------|------|
| 규칙 | "에러 처리는 try-catch 말고 Result 타입 써" |
| 금지 | "any 타입 쓰지 마" |
| 실행 방법 | "테스트는 `bun test --filter=unit`으로 돌려" |

이런 건 코드에 안 적혀있으니까, 규칙 파일에 적어둬야 해.

---

## 📤 Output — 관찰하고 배우기

여기가 진짜 핵심이야. 3단계로 작동해.

### 1단계: 기록하기 (Hook)

Claude가 코딩할 때 하는 모든 행동을 몰래 기록해.

```
Claude가 파일 검색함 → 📝 기록!
Claude가 파일 읽음   → 📝 기록!
Claude가 코드 수정함 → 📝 기록!
Claude가 테스트 돌림 → 📝 기록!
```

이 기록하는 녀석(Hook)은 바보야. 판단 같은 거 안 해. 그냥 받아서 노트에 적기만 해. 받아쓰기 하는 학생처럼.

기록은 SQLite라는 작은 데이터베이스에 쌓여. 마치 일기장에 차곡차곡 쓰는 것처럼.

```
Hook(받아쓰기) → collector(중계자) → SQLite(일기장)
```

### 2단계: 분석하기 (Background Worker)

여기서 두 번째 AI가 등장해.

사용자가 Claude랑 코딩하는 동안, 뒤에서 또 다른 Claude가 몰래 일기장을 읽으면서 분석해.

```
사용자 ←→ Claude (코딩 중)           ← 앞에서 일하는 AI

          SQLite (일기장)            ← 중간 창고
              ↑
         Background Worker (분석 AI) ← 뒤에서 관찰하는 AI
```

이 "분석 AI"는 관찰만 해. 절대 코드를 건드리거나 파일을 수정하지 않아. 마치 교실 뒤에 앉아서 수업을 참관하는 선생님처럼.

#### 분석 AI는 어떻게 만들어?

`@anthropic-ai/claude-code`라는 도구의 `query()` 함수를 써서 Claude를 하나 더 띄워. 이 Claude는 별도의 프로세스(프로그램)로 돌아가.

```
query() 호출
  │
  ├── Claude 프로그램 찾기
  ├── 모델 설정 (claude-sonnet-4-5)
  ├── Claude 서브프로세스 생성    ← 새 Claude 하나 더 켜는 거!
  │     └── 메시지를 하나씩 먹여줌 (AsyncIterator)
  │     └── Claude가 XML로 대답함
  └── 대답을 파싱해서 DB에 저장
```

핵심 특징:
- **모든 도구 사용 금지** — 파일 읽기, 쓰기, 검색, 터미널 전부 막혀있음. 관찰만 가능
- **세션 이어가기** — 처음엔 새로 시작, 두 번째부터는 이전 대화를 이어받음 (resume)
- **좀비 방지** — 분석 AI가 먹통이 되면 5초 후 강제 종료, 5분마다 고아 프로세스 청소

#### 분석 AI는 뭘 보는 거야?

5가지를 측정해:

| 뭘 보나 | 쉬운 설명 |
|---------|----------|
| **찾기 쉬움** | 원하는 파일을 몇 번 검색해야 찾았나 |
| **읽기 쉬움** | 파일을 100줄 읽었는데 고친 건 3줄이면, 97줄은 쓸데없이 읽은 거 |
| **예측 가능** | 비슷한 파일인데 매번 확인해봐야 하면 예측이 안 되는 거 |
| **설명이 잘 됨** | 같은 걸 매번 다시 찾으면 설명이 부족한 거 |
| **독립적** | 하나 고치려고 여기저기 10군데를 봐야 하면 너무 얽혀있는 거 |

### 3단계: 개선하기 (Output)

분석 AI가 패턴을 발견하면 3가지를 해:

**자동으로 하는 것:**
```
.claude/rules/error-handling.md 생성
→ "에러 처리는 Result 타입을 사용한다"
  (try-catch → Result 변환이 5번 연속 관찰됐으니까)
```

**CLAUDE.md에 추가:**
```
"테스트 실행: bun test --filter=unit"
  (매번 실패 후 재시도로 발견되는 명령어니까)
```

**큰 변경은 제안만:**
```
.claude-auto-context/offers/001-split-utils.md
→ "utils.ts를 3개로 쪼개는 게 어때요?"
  (10번 중 8번 읽었는데 매번 조금만 쓰니까)
```

큰 변경은 자동으로 안 하고 **제안서(offer)**를 써놔. 사용자가 `/cac-apply`를 입력해야 실행돼. 마치 "이렇게 바꿀까요?"라고 물어보는 거야.

## 전체 그림 한 눈에

```
🧑 사용자: "인증 버그 고쳐줘"
     │
     ▼
🤖 Claude (앞에서 코딩)
     │
     ├── 파일 검색  → 📝 기록
     ├── 파일 읽기  → 📝 기록
     ├── 코드 수정  → 📝 기록
     ├── 테스트     → 📝 기록
     │
     ▼
📓 SQLite 일기장
     │
     ▼
🔍 분석 AI (뒤에서 관찰)
     │
     ├── 📋 규칙 파일 자동 생성 → 다음에 Claude가 자동으로 읽음
     ├── 📝 CLAUDE.md 업데이트 → 실행 방법 등 메모
     └── 💡 제안서 작성         → 사용자가 승인하면 적용
```

**한 마디로:** Claude가 코딩하는 걸 다른 Claude가 지켜보면서, 프로젝트를 점점 더 일하기 좋은 구조로 만들어주는 시스템이야.
