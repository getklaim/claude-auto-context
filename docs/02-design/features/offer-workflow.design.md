# Design: Offer Workflow (알림 → 승인 → 적용)

> Plan 참조: `docs/01-plan/features/offer-workflow.plan.md`

## 1. 현재 상태 분석 & 발견된 문제

### offer 파일 포맷 불일치

`create-offer` SKILL.md가 정의한 템플릿:
```markdown
# Offer: {title}
## Status
pending
## Category
structure | pattern | organization
## Proposal
...
```

실제 생성된 `001-lock-file-stale-on-crash.md`:
```markdown
# 001 — Lock File Not Cleaned Up on Worker Crash or SIGKILL
## Summary
...
## Proposed Remediations
...
```

**`## Status` 필드가 없고, 제목 포맷도 다르다.**

→ 알림 스캔 로직에서 이 불일치를 **양방향으로 대응**해야 한다.

## 2. 컴포넌트 설계

### 2.1 UserPromptSubmit Hook — 알림 주입

**파일**: `scripts/on-user-prompt-submit.sh`

**변경 전**:
```bash
cat | bun "$PLUGIN_ROOT/.claude-auto-context/collector.mjs" UserPromptSubmit
exit 0
```

**변경 후 로직**:
```bash
#!/bin/bash
PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-$(cd "$(dirname "$0")/.." && pwd)}"
PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$(pwd)}"
OFFERS_DIR="$PROJECT_DIR/.claude-auto-context/offers"

# 1. 기존 기능 유지: stdin을 collector에 전달
#    stdin은 한 번만 읽을 수 있으므로 tee로 분기
INPUT=$(cat)
echo "$INPUT" | bun "$PLUGIN_ROOT/.claude-auto-context/collector.mjs" UserPromptSubmit

# 2. pending offer 스캔
if [ -d "$OFFERS_DIR" ]; then
  PENDING_FILES=()
  PENDING_TITLES=()

  for f in "$OFFERS_DIR"/*.md; do
    [ -f "$f" ] || continue

    # applied 상태면 스킵
    if grep -q "^applied$" "$f" 2>/dev/null; then
      continue
    fi
    # rejected 상태면 스킵
    if grep -q "^rejected$" "$f" 2>/dev/null; then
      continue
    fi

    # 제목 추출: 첫 번째 # 라인
    TITLE=$(grep -m1 "^# " "$f" | sed 's/^# //')
    [ -z "$TITLE" ] && continue

    BASENAME=$(basename "$f" .md)
    ID=$(echo "$BASENAME" | grep -o '^[0-9]*')

    PENDING_FILES+=("$f")
    PENDING_TITLES+=("$ID. $TITLE")
  done

  COUNT=${#PENDING_FILES[@]}

  # 3. pending offer가 있으면 알림 출력
  if [ "$COUNT" -gt 0 ]; then
    echo "─────────────────────────────────────────────────"
    if [ "$COUNT" -eq 1 ]; then
      echo "Auto Context — 1건의 Offer 대기 중"
    else
      echo "Auto Context — ${COUNT}건의 Offer 대기 중"
    fi
    echo "─────────────────────────────────────────────────"
    for t in "${PENDING_TITLES[@]}"; do
      echo "  $t"
    done
    echo "/cac-apply 로 적용"
    echo "─────────────────────────────────────────────────"
  fi
fi

exit 0
```

**설계 결정**:

| 결정 | 근거 |
|------|------|
| `applied` / `rejected` 문자열 grep으로 필터 | `## Status` 헤더 없이도 동작. 파일 어딘가에 `applied`가 있으면 적용 완료로 판단 |
| 나머지는 모두 pending 취급 | `## Status\npending`이 없는 기존 offer도 자연스럽게 포함 |
| stdin을 변수에 저장 후 pipe | stdin은 1회 소비이므로 `cat`으로 먼저 캡처 |
| bun 의존 없음 (순수 bash) | hook은 <100ms 이내 완료해야 하므로 bun 기동 오버헤드 회피 |
| 제목은 첫 `# ` 라인 | 템플릿(`# Offer: ...`)이든 실제(`# 001 — ...`)이든 첫 h1 추출 |

**성능**: offers 디렉토리에 파일이 수십 개 이하이므로 for loop + grep은 수ms 이내 완료.

### 2.2 `/cac-apply` 스킬

**파일**: `.claude/skills/cac-apply/SKILL.md`

```markdown
---
name: cac-apply
description: Review and apply structural offers from Auto Context.
  USE WHEN user types /cac-apply or mentions applying offers.
---

# Apply Offer

Review and apply pending structural offers generated by Auto Context.

## Arguments

- No argument: list all pending offers, ask user to select
- `{id}`: apply specific offer by ID (e.g., `/cac-apply 001`)
- `all`: apply all pending offers sequentially

## Procedure

### Step 1: Scan pending offers

1. Read all `.md` files in `.claude-auto-context/offers/`
2. Filter: skip files containing the line `applied` or `rejected`
3. Remaining files are pending offers

### Step 2: No argument — interactive selection

1. Display numbered list of pending offers (ID + title)
2. If 0 pending: output "대기 중인 offer가 없습니다." and stop
3. Use AskUserQuestion to let user select which offer(s) to apply

### Step 3: Apply selected offer

For each selected offer:

1. Read the full offer file
2. Identify the proposal section (`## Proposal` or `## Proposed Remediations`
   or any section describing what to change)
3. Execute the proposed changes:
   - Read target files mentioned in proposal
   - Apply the suggested modifications (Write/Edit)
   - If proposal involves file splits: create new files, update imports
4. Verify: run existing tests if available (`bun test`, `npm test`, etc.)
5. Update the offer file: add `## Status` section with value `applied`
   and `## Applied At` with ISO timestamp
6. Output summary of changes made

### Step 4: `all` argument

Repeat Step 3 for every pending offer, sequentially.
Stop on first failure and report which offer failed.

## Status Update Format

After applying, append to the offer file:

```
## Status
applied

## Applied At
{ISO 8601 timestamp}

## Changes Made
- {file}: {description}
- {file}: {description}
```

## Error Handling

- If offer references files that don't exist: skip with warning
- If tests fail after applying: revert changes, mark offer as
  `failed` instead of `applied`, report to user
- If offer is ambiguous: ask user for clarification before proceeding

## Anti-Patterns

- Do NOT apply without reading the full offer first
- Do NOT skip test verification if tests exist
- Do NOT modify the offer's Problem/Evidence sections
```

**설계 결정**:

| 결정 | 근거 |
|------|------|
| `## Proposal` + `## Proposed Remediations` 양쪽 지원 | 기존 offer와 템플릿 offer 모두 대응 |
| 상태를 파일 끝에 append | 기존 내용 손상 없이 상태 추가. `## Status` 없던 파일에도 적용 가능 |
| 테스트 실패 시 revert | 안전장치 — 구조 변경은 위험도가 높으므로 |
| `Changes Made` 섹션 추가 | 사후 감사 추적 가능 |

### 2.3 상태 전이 모델

```
[offer-agent 생성]
      │
      ▼
   pending ──── /cac-apply ────► applied
      │                            │
      │                            └── Applied At: 2026-03-03T...
      │                                Changes Made: [...]
      │
      └──── /cac-apply (실패) ──► failed
      │
      └──── (향후) /cac-reject ─► rejected
```

**상태 판별 로직** (grep 기반):
- 파일에 `^applied$` 있음 → applied
- 파일에 `^rejected$` 있음 → rejected
- 파일에 `^failed$` 있음 → failed
- 그 외 → pending (기본값)

이 방식은 `## Status` 헤더 유무에 의존하지 않아 기존 offer 파일과 호환된다.

## 5. 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| offers/ 디렉토리 없음 | 알림 스킵, `/cac-apply`는 "offer 없음" 출력 |
| offer 파일이 .md가 아닌 경우 | 무시 (*.md만 스캔) |
| 동일 offer 중복 적용 시도 | `applied` 라인이 이미 있으므로 pending 목록에서 제외 |
| 제안 대상 파일이 삭제된 경우 | 경고 출력 후 스킵, offer 상태는 변경하지 않음 |
| 테스트가 없는 프로젝트 | 테스트 단계 스킵, 적용만 수행 |
| offer 내용이 모호해서 자동 적용 불가 | AskUserQuestion으로 사용자에게 확인 |

## 6. 구현 순서

```
1. scripts/on-user-prompt-submit.sh 수정  (알림)
   └── 검증: pending offer 있는 상태에서 프롬프트 입력 → 알림 표시 확인

2. .claude/skills/cac-apply/SKILL.md 생성  (적용 + 상태 전이)
   └── 검증: /cac-apply 실행 → offer 목록 → 적용 → 상태 변경 확인
```
